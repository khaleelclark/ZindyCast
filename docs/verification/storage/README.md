## Public API and integration

`new SharedStorage({ path, clock?, maxEntries?, maxBytes?, maxEntryBytes?, maxLeases?, maxQuotaEvents?, maxDiskBytes?, busyTimeoutMs?, providers? })` opens one synchronous connection. Use the **same dedicated local database path and identical limits/provider configuration** in API and worker. Parent directory creation and file permissions belong to deployment configuration. Configuration is persisted; a mismatch fails instead of letting another process silently raise budgets. Schema version 1 is recorded with configuration; future schema/configuration changes require an explicit migration. This database stores disposable cache alongside coordination state; do not delete it to clear cache because that also resets quota reservations.

- `get(key): CacheRecord | null`: returns parsed `JsonValue`, `retrievedAt`, `expiresAt`, `staleUntil`, and `freshness`. All timestamps are integer Unix milliseconds. Fresh is `now < expiresAt`; stale is `expiresAt <= now < staleUntil`; at the stale deadline the entry is unavailable. A retrieval timestamp in the future returns unavailable. Retrieval is never rewritten by a read and is not a substitute for source issue time. Retain full provider provenance in the JSON payload and validate its runtime schema after loading; storage does not validate weather contracts.
- `set(key, value, times, lease?): boolean`: accepts plain finite JSON and ordered deadlines, rejects future retrieval or already unusable data, and rejects older retrievals. With a lease, rejects expired/superseded ownership in the same transaction as publication. Lease key must equal cache key. Return false means the write lost its lease or a newer retrieval already exists. Oversized/malformed values throw. Store JSON-compatible data, not arbitrary class instances. Keys must include provider/dataset/coordinates/variables/time range/calculation revision as appropriate.
- `acquireLease(key, owner, ttlMs): Lease | null`: exclusive across connections/processes, including repeat requests by the same owner. Returns a random token with expiry; TTL is 1 ms–24 hours. Null means held or lease capacity exhausted. `releaseLease(lease): boolean` only removes matching key, owner and token; a late release cannot remove a replacement lease. Leases recover after expiry without the original process. There is no renewal API in this bounded implementation.
- `reserveQuota(provider, weight): QuotaResult`: atomically checks all four limits and records usage only when all permit it. Defaults to configured provider `open-meteo` at 600/minute, 5,000/hour, 10,000/day, 300,000/month. Other providers require explicit configured limits. Unknown providers and nonpositive/nonfinite weights throw. Weights round **up** to integer thousandths; callers must calculate a conservative request weight before sending, including variable/date/location multipliers. This method does not derive cost from a URL. No refunds: upstream failures and crash windows can still consume quota. Denials have `reason: quota|capacity`, blocking window names and nullable `retryAt`; retryAt is only the earliest useful retry, not guaranteed admission. A weight above a total window limit must be split/rejected by the caller.
- `cacheUsage()` reports row count and charged UTF-8 bytes (key plus serialized JSON). `diskUsage()` separately measures actual database, WAL and SHM files. `cleanup(batchSize=1000)` deletes at most that many expired rows per table (maximum batch 10,000), attempts a truncating WAL checkpoint, and reports row counts, disk bytes and `checkpointBusy`. `close()` closes the connection.

Refresh sequence: read cache; if refresh is needed, acquire the cache-key lease; **re-read cache after acquisition** because another refresher may have completed; reserve provider quota; fetch with a bounded timeout shorter than the lease; validate upstream data; publish with `set(..., lease)`; release in `finally`. Denied quota means do not fetch. A failed lease means serve permitted stale data or wait/retry outside SQLite. Do not hold a database transaction across a network call. An expired lease can allow a second fetch while the old process is still running; fencing prevents the old process publishing, but cannot cancel an already issued HTTP request. Process-local promise deduplication can complement these cross-process leases.

## Quota policy and bounds

Minute/hour/day are exact rolling 60-second/60-minute/24-hour windows. Month is a **conservative rolling 31 days**, which can deny earlier than calendar-month accounting and prevents boundary bursts. These are application accounting decisions, not claims about the provider's undocumented enforcement algorithm. Usage exactly at `now - window` is expired. Successful reservations at the same millisecond/provider coalesce. Reservations persist through restart. All processes must use the shared database and reserve every call; usage from other applications sharing the upstream IP is outside this ledger. Current-weather priority/headroom and retry scheduling remain integration work.

Defaults: 1,000 cache entries, 32 MiB charged cache bytes, 2 MiB per entry, 1,000 lease entries and 50,000 distinct provider/millisecond quota entries. Cache eviction uses oldest write time (not LRU) and preserves the just-written item; replacement correctly accounts for the previous entry. Cache keys/lease owners are bounded to 2,048 UTF-8 bytes and JSON depth to 64. Quota capacity fails closed without deleting unexpired usage. Small private-app usage should stay far below it, but exceeding capacity can deny calls despite remaining upstream budget. Automatic lease/quota cleanup deletes at most 1,000 expired rows per operation. Explicit periodic cleanup is required even when no upstream requests occur.

`BEGIN IMMEDIATE` encloses reservation, lease acquisition and cache publication. Busy timeout defaults to 1,000 ms, configurable 0–5,000 ms; SQLite lock and disk errors surface to callers. These operations synchronously block the event loop while executing/waiting, so API integration must handle storage errors without issuing an unbudgeted fallback request. SQL uses bound values. Clock regressions below a persisted mutation high-water mark fail closed; restore host time before resuming mutations. Large forward clock corrections can expire leases/budgets early, so the shared local host clock must remain trustworthy.

## Physical disk maintenance and limits

WAL mode, `synchronous=FULL`, 256-page autocheckpoint and 1 MiB `journal_size_limit` are configured. The default 128 MiB physical budget is checked before admitting cache/lease/quota mutations; `max_page_count` also caps the main database. Database, WAL and SHM bytes are all measured. This is **not a strict filesystem-byte ceiling**: an admitted transaction can overshoot, readers can pin WAL frames, and the journal-size pragma limits retained size after checkpoint rather than live WAL growth. Once the measured budget is reached further admissions fail until cleanup/maintenance. No unbounded retry is performed.

Deletes free SQLite pages for reuse but do not shrink the main database. `cleanup()` attempts WAL truncation and explicitly reports busy readers. Run cleanup periodically in the worker, inspect physical bytes, and retry a busy checkpoint later outside request handling. If the main file's high-water allocation consumes the disk allowance, stop API/worker, back up the coordination database consistently and run SQLite `VACUUM` in a maintenance window using the built-in driver, then reopen both. Full compaction is deliberately not performed on request paths; allow temporary disk space for it. Never remove a live WAL/SHM file or erase unexpired quota state to recover room. Crash/power-loss recovery and operational backup/restore are broader release checks, not established by these tests.
