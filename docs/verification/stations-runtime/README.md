# Bounded H2 GHCN-Daily runtime adapter

Implemented September 11, 2026 in `packages/stations/src/index.ts`. Primary format/flag reference: [NOAA GHCN-Daily readme](https://www.ncei.noaa.gov/pub/data/ghcn/daily/readme.txt), checked September 11 (readme version 3.34). Existing [station research](../../research/station-history.md) and its raw files are preserved. The documentation version does not establish the version of an individual live station file.

## Server interface

```ts
getStationHistory(query: StationQuery, signal?: AbortSignal): Promise<StationData>
parseStationDaily(completeFile: string, query: StationQuery, retrievedAt: string): StationData
// StationQuery = { stationId: string; startDate: string; endDate: string }
```

Exports `StationQuerySchema`, `StationValueSchema`, `StationDaySchema`, `StationDataSchema`, inferred `StationQuery`, `StationValue`, `StationData`, `StationQueryJsonSchema`, `StationDataJsonSchema`, `stationElements`, `STATION_MAX_BYTES`, and `StationError`. Error codes: `invalid_request`, `provider_error`, `rate_limited`; optional `httpStatus` and `retryAfterSeconds`. Caller cancellation preserves its reason. Schemas, types, pure normalization/coverage helpers and cross-field refinements now live in browser-safe `packages/contracts/src/stations.ts`. The station adapter imports/reexports the same schema objects; browser code imports `@zindycast/contracts`, never the server package. `StationResponseSchema`/`StationResponse` define the success envelope with literal `fresh` freshness; errors use the common API error shape.

JSON schema artifacts are generated by `npx tsx docs/verification/stations-runtime/export-schemas.ts`. JSON Schema supplies the structural contract only. Zod additionally checks real calendar dates, inclusive span, exact daily sequence, station/source identity, cell conversions/flags/missingness and coverage counts. Consumers validating restored/cached data must use `StationDataSchema`, not structural JSON Schema alone.

Explicit station ID must match `US[A-Z0-9]{9}`; 1–366 inclusive valid Gregorian calendar labels, years 0001–9999. This is syntactic date acceptance, not a NOAA availability claim. Network queries reject dates after UTC today; today's label is not a complete-day guarantee. The pure parser accepts historical/reproducibility selections independent of the current clock.

One GET of `https://www.ncei.noaa.gov/pub/data/ghcn/daily/all/<stationId>.dly`; no retries, redirects, candidate lookup or national downloads. 15-second network/body deadline, 15 MiB decompressed byte ceiling, HTTP 200/text/plain required; partial content and malformed data fail. No Range header. The complete file is fetched even for a short date selection: callers must coordinate cache/concurrency and bandwidth accordingly. A cutoff at a syntactically complete row cannot be detected without an external source checksum; HTTP framing plus fixed-width validation is not proof of historical completeness.

## JSON semantics and UI requirements

`query` retains the explicit station identity and selected date labels. `station` returns the same ID, with name/coordinates/elevation null and `metadataStatus: not_retrieved`; no research metadata is silently injected into live responses. `timeContext` declares source daily labels; timezone, observation time and interval endpoints remain null. Do not convert a daily label into a midnight UTC instant or infer local/DST alignment. Station observation periods and HOMR epochs remain separate future work.

`days` contains every selected calendar label, each with `TMAX`, `TMIN`, `PRCP` cells. `rawValue` preserves the fixed-width integer, including -9999; absent monthly rows have null raw values. `value` is the SI conversion (°C or mm) for every nonmissing source number, **including QC-flagged numbers**. It is not a measurement accepted for statistics. Missing source -9999 and absent monthly records both have null SI values but distinct reasons (`source_missing`, `absent_month`). Flags preserve exactly one source character, including spaces and lowercase; absent records have null flags.

`qcStatus` is missing / unflagged / flagged / unknown_code. Unknown syntactically valid alphanumeric codes are retained in `unknownFlags`, not promoted to known-good flags; invalid flag characters fail parsing. Measurement flag T produces `trace: true`; P produces `presumedZero: true`, even on a missing sentinel. Trace numeric zero is not exact measured zero, and presumed zero is not confirmed dry weather. Nonmissing values with blank quality flags still count as `unflagged` even if measurement/source flags require review. Source S daily summaries can derive from hourly synoptic reports; the `station_daily_summary` classification avoids implying every number was directly measured over a verified local 24-hour period.

`coverage` provides per-element exact denominators: expected, present, missing, absentMonth, sourceMissing, unflagged, flagged, unknownQuality, unknownFlags, trace, presumedZero. Present partitions into unflagged + flagged + unknownQuality; missing partitions into absentMonth + sourceMissing. Flag diagnostic counts may overlap those partitions. `jointUnflagged` counts dates with all three nonmissing and quality-blank. `eligibility` always says `not_assessed`. No coverage thresholds, accepted-value aggregate, precipitation total, ranking, splice, normals, hourly values or WBGT is supplied. Other elements (including multiday totals) are validated structurally but not substituted for TMAX/TMIN/PRCP.

`provenance` supplies fixed NOAA/dataset identity, exact request and documentation URLs, adapter version and retrieval time. Dataset release version, source issue/update times remain null. Retrieval is not source freshness. Live output is NOAA data; tests use clearly isolated preserved research evidence, with no fixture fallback in runtime.

## H2 REST integration

`registerStations(app, cached)` in `apps/api/src/stations.ts` registers `GET /api/v1/stations/history?stationId=USC00021282&startDate=2020-01-01&endDate=2020-01-01`. The strict shared query rejects extra/repeated fields, invalid IDs/dates, over-366-day spans and future dates before fetching. Success is `{status: "success", freshness: "fresh", data: StationData}`. Invalid input returns 400; shared budget/provider 429 retains Retry-After; upstream/validation/deadline failures return 502. No live requests were added for integration.

The cache key fixes dataset/adapter version, three elements, source daily-label basis and exact station/date selection. The cache schema validates all cross-fields plus exact query equality on reads and fetched output. TTL is one day, stale window zero, and the response schema also rejects stale entries inherited from another policy. A shared `noaa` quota reservation has conservative weight 1 per full-file request; refusal never triggers an unbudgeted fallback. The route's outer 12-second abort covers fetch/body, with elapsed-time rejection after synchronous parsing, leaving margin before the shared 15-second lease. This is not a hard CPU preemption guarantee.

Only the normalized selected 1–366-day JSON is cached, never the raw <=15 MiB file. Different date selections may download the same complete file separately; quota weight 1 counts requests, not bytes. The existing shared concurrency/size budgets still apply, and deployments must account for full-file bandwidth. There is no cross-selection full-file cache, automatic station discovery, background job or stale fallback.

Route regression tests reside in owned `packages/stations/src/route.test.ts`: real Fastify injection and in-memory shared storage exercise schema identity, validation before fetch, repeat-query cache hit, NOAA quota, Retry-After/errors, wrong cached selection, normalized cache size/TTL, stale rejection and a stalled fetch aborted at 12 seconds. Existing parser tests continue to validate shared cross-refinements against preserved research fixtures.

Integration verification: `npx tsx --test packages/stations/src/index.test.ts packages/stations/src/route.test.ts` passed 12/12; `npm run typecheck` and `npm run build` passed. Lead supplied the root contract reexport and API dependency. Route tests explicitly use `APP_PROVIDER_LIMITS` because bare `SharedStorage` defaults only to Open-Meteo; unconfigured NOAA quotas fail closed. Zero live upstream calls, installs or service changes in this integration wave.
