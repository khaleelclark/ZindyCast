## Finding

**The reproduced satellite image is functioning gray thermal infrared, with coarse source detail. No backend projection or empty-image fault was demonstrated.** The current source is `satellite:goes_longwave_imagery`, GOES Band 14 (11.2 µm), nominal 2 km detail and five-minute cadence. It is cloud/surface thermal imagery, not a photographic ground map or precipitation radar. The source PNG is fully opaque; applying it above the basemap can gray/dim roads even where no bright clouds appear. The current app uses 65% weather opacity, so this is a plausible contributor to the reported appearance, not a browser-measured screenshot diagnosis.

Live GetCapabilities and one EPSG:3857 GetMap through the existing request builder both returned HTTP 200. Requested geographic rectangle `[-82.17,28.2,-80.17,29.51]` surrounds 28.858,-81.170; projected width/height ratio 1.337 approximately matches 800/600. The exact URL, headers, bytes, hashes and retrieval times are in [live.json](live.json). Catalog retrieved 17:00:56.042Z; requested latest advertised satellite time 16:53:00Z; image retrieved 17:00:56.467Z. No Warning header. Actual source time is still not independently confirmed by the PNG.

[Florida image](florida-satellite.png) was visually inspected: dark gray background and lighter cloud-like structures, no error text. Offline Chrome canvas decoding found 800×600 pixels, all 480,000 opaque and grayscale, 132 unique RGBA values, intensity range 54–186. This rules out blank/fully transparent/error output in this sample. It does not independently verify absolute cloud geolocation; no coastline reference is visible in this close thermal crop. Existing independent Mercator-corner and axis-order tests pass.

The [retained live NOAA capabilities](capabilities.xml), from the [official fixed WMS endpoint](https://nowcoast.noaa.gov/geoserver/ows?service=WMS&version=1.3.0&request=GetCapabilities), also advertise global longwave at approximately 3 km, hourly updates and 2–3-hour latency. They advertise `satellite:goes_visible_imagery`, Band 2 at 0.5 km/five minutes for daylight cloud viewing. Visible is a possible future, explicitly labeled daylight option; it is not implemented or image-verified here and must not silently replace all-hours infrared. Neither product is street-level photography.

## Why forecast has blocks

[IEM's primary HRRR service documentation](https://mesonet.agron.iastate.edu/GIS/model.phtml) specifies a 0.02°×0.02° raster for simulated reflectivity 1000 m AGL. Around this Florida location, that is approximately 1.95 km east-west by 2.23 km north-south. These are raster spacings, not effective forecast accuracy/resolving power. Web Mercator 256-pixel tile spacing is `156543.033928*cos(latitude)/2^z` metres: 1,071 at z7, 536 at z8, 268 at z9. Thus z7 already samples more finely than the published raster; enlarging source blocks at a neighborhood view is expected. More requested tile pixels cannot add meteorological information.

The backend and frontend z7 maximum is an application budget choice, not an IEM documented maximum. One additional permitted GET tested explicit historical run `202609111400`, F0180, Florida XYZ **9/140/213**. It returned HTTP 200, 390-byte 256×256 PNG, with 80 opaque pixels and 65,456 transparent pixels. See [headers](forecast-z9.json) and [image](forecast-z9.png). This establishes acceptance of that single higher-zoom request, not universal supported maximum, meaningful visual improvement, current future availability, or coverage. Its 17:00Z valid time had already passed at 17:01:32Z retrieval; deliberately retained as historical transport evidence only. No latest metadata request or mutable `0` run was used. Transparent pixels do not prove dry weather.

## Concrete recommendation to lead

1. Keep the existing source, projection and bounds. Label satellite concisely **Infrared clouds · ~2 km detail** and add a brief expanded explanation of thermal cloud/surface patterns. Consider lower satellite opacity to preserve geographic context. Test legibility against actual roads in the browser; this audit does not prescribe an untested percentage.
2. Keep forecast z7 budget initially. Label **HRRR forecast · coarse model grid** and keep regional default framing. Smooth display interpolation can soften jagged edges, but must not be described as better data resolution. Observed raster already uses linear sampling; concurrent frontend source now also explicitly uses linear sampling for forecast (not changed by this agent).
3. Do not promise z9 eliminates blocks. If choosing z8/9 for presentation after a browser comparison, coordinate frontend source limits, protocol validation, shared schema, backend validation and tests together. Keep 30 uncached/minute, concurrency two, no prefetch and existing cache bounds. At fixed geographic extent, raising zoom one level can quadruple the required tile count; responsiveness/budget must be measured.
4. A future visible-cloud option offers genuinely finer documented source sampling in daylight, but requires its own bounded imagery, nighttime/missing-state, timeline and browser audit. No palette conversion, fake precision or paid source is needed for the immediate labels/opacity work.
