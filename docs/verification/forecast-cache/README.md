# Future radar cache audit — 2026-09-11

Existing server tiles are cached for five minutes by pinned model run/frame and XYZ, with no stale fallback. The browser retains at most 32 decoded tiles / 16 MiB, expiring at the earlier of five minutes, forecast valid time, or model-run eligibility deadline. Cache entries are pruned on access and every 15 seconds while the map is mounted; unmount clears decoded memory. HTTP no-store intentionally does not disable these application caches.

Fixed a late-response edge case: a tile finishing after its forecast valid time could be pruned from the cache and then returned from the raw-response fallback. Eligibility is now checked before queued requests, after cache-copy completion, after decoding, and before returning. Expired results do not populate memory, display, or trigger upstream-failure cooldown. Exact cached backtracking and existing quotas are unchanged.

Verification: typecheck and isolated production build passed (existing MapLibre dynamic-import warning). Five frontend unit tests pass, including new slow-response/expiry/no-second-request coverage. Five API cache tests pass, including exact five-minute cache reuse and rejection once the valid time passes. Actual isolated Chrome forecast audit also passed (six total frontend tests): cached playback/backtracking, slider debounce, cooldown recovery, polling, desktop/mobile layout and lifecycle checks. APIs used fixtures and external tiles were blocked. Reproduce: FORECAST_MAP_DIST=/tmp/zindycast-cache-expiry-dist npx tsx --test apps/web/src/forecast-map.test.ts.
