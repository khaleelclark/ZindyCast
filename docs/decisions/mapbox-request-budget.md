# Shared Mapbox admission budget — September 12, 2026

User authorized a deployment host-wide counter and automatic standard-map fallback. Limit is190,000 permits across all devices using the updated client. Each actual Mapbox tile fetch first reserves one permit by POST /api/v1/maps/mapbox/admission. Every permitted attempt counts, even if HTTP-cached, cancelled after reservation or failed upstream. No refunds, client batches, or count chosen by the requester. Standard OSM, NOAA and IEM calls do not consume this budget.

Counter lives in the existing coordination.sqlite as zc_mapbox_budget, with atomic BEGIN IMMEDIATE reservations and synchronous FULL/WAL durability. Day buckets retain reservations for32–33days, preventing premature reset without knowing Mapbox's billing-cycle start/timezone. Maximum33 active buckets; this is intentionally more conservative than a monthly reset. Shared configuration and other provider quota cleanup are unchanged. Limit check occurs inside the write transaction, so competing connections cannot both claim the last permit. Clock rollback, corrupt/future bucket, disk/DB failure deny admission. Application must default to standard map on any reservation failure or malformed response.

API success200: {allowed:true,used,limit:190000}; budget denial429: {allowed:false,used,limit:190000,reason:'limit'}; unavailable503: {allowed:false,limit:190000,reason:'unavailable'}. POST only, no body or query; no-store; rejects cross-site fetches in addition to production trusted-origin boundary. Admission contacts no external provider and holds no Mapbox token.

This is an application request budget, not Mapbox's invoice count. Prior Mapbox use before activation is not reconstructed; the10,000 buffer remains. Old open app versions without admission, other applications and direct use of the public token can bypass the application counter. Users must accept the new update on each device. URL restriction remains necessary; this is not an account spending-cap guarantee. Do not destroy/reset or restore an old coordination database to replenish quota. Existing persistent backup must retain this table.

A missing budget table during ordinary upgrade is created once by SharedStorage alongside its existing tables; no separate database, package or worker process. Offline/failure sticky fallback prevents repeat traffic until explicit retry, which still requires server admission. Re-enabling Mapbox cannot bypass the cap.
