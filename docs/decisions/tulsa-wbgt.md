### Calculator trace

The following describes the retrieved code, not a recommended implementation:

1. `getNDFD` calls MapClick JSON at selected coordinates. It combines the first daytime forecast maximum (today or tomorrow) with a current station dew point and wind. Sky text from the forecast maps to 0/20/60/100 percent, otherwise 50, despite the cloud slider tooltip referring to observations. Altimeter pressure in 26–34 inches Hg becomes hPa using 33.8639; otherwise pressure defaults to 1000 hPa. This is not a consistent current-time meteorological sample, and altimeter is not surface pressure.
2. `get_max_solar_flux(latitude,year,month,day)` estimates maximum daily solar flux with declination/orbital and polynomial attenuation terms. It uses no current hour or longitude. As written, `Solcons` ends its denominator with a JavaScript comma expression `(...,2)`, yielding a constant factor0.5 rather than the apparent intended orbital expression; this is static code interpretation, not measured behavior. The globe code fixes cosine zenith at 0.707; cloud fraction is assigned to the direct-beam coefficient and one minus cloud fraction to diffuse. Do not substitute this for supplied instantaneous GHI. Its leap helper uses divisible-by-4 and not-divisible-by-10, which misclassifies years such as 2000/2020; date sliders permit invalid dates and date/latitude slide callbacks do not themselves recalculate WBGT.
3. Globe calculation floors wind at 4 mph, converts to m/hour using 1609, and uses the paper's linearized form `TgC=(B+C*TaC+7680000)/(C+256000)` before Fahrenheit conversion. It uses coefficient 0.315 and a Celsius fourth-power term. The script applies emissivity as `(0.575*ea)^(1/7)`, whereas paper equation 5 places 0.575 outside the power. These are further reasons not to equate the page with the paper or Liljegren.
4. Ordinary wet-bulb starts from temperature/dew point and a pressure-dependent psychrometric expression, then takes five correction iterations. A separate empirical adjustment adds radiation and subtracts wind to produce natural wet-bulb, clamps it against ordinary wet-bulb, then clamps to 50–85°F. The latter ceiling can override the preceding clamp. Globe and natural wet-bulb therefore follow different wind floors. This is not the existing iterative Liljegren heat/mass-balance calculation.
5. Final outdoor weighting is 70% natural wet-bulb, 20% globe and 10% air temperature. Display rounds to whole Fahrenheit before selecting colors at 83, 86, 90 and 93°F. Those color boundaries differ from the written action table. The unused `shady` calculation does not define an app sun/shade mode. The heat-index branch is a separate polynomial with humidity corrections, not WBGT.

The linked paper develops a globe approximation, with three preliminary September 2010 Tulsa comparisons. It does not establish nationwide family categories, validate the current website's combined calculator, or supply individual safe time. Its text also mentions both 0.437 and 0.315 for a convection coefficient. Retain existing validated Liljegren rather than silently adopting or repairing the prototype. The nine page examples omit sufficient time/radiation/pressure provenance to be independent reference tests for our calculation.

## Reference scale, separate from guidance

Use the page's **written table** as a named informational reference. Do not borrow its calculator colors, invent low/moderate/high labels, reproduce exposure countdowns, or claim an official warning. The source does not provide an explicit eligible family population, acclimatization model or complete equality convention.

| Printed °F band | Unambiguous interior used by helper | Endpoint treatment |
|---|---|---|
| <80 | value <80 | 80 unresolved |
| 80–85 | 80 < value <85 | 80/85 unresolved |
| 85–88 | 85 < value <88 | 85/88 unresolved |
| 88–90 | 88 < value <90 | 88/90 unresolved |
| >90 | value >90 | 90 unresolved |

85 and 88 meet hyphenated intervals; 80 and 90 meet a hyphenated interval and an explicitly strict outer interval. The page gives no formal endpoint convention. Treating all four exact endpoints as unresolved is an explicit conservative product choice, not a claim that the page explicitly excludes them. Do not fill the gaps by rounding or choose the more severe row automatically.

`TULSA_WBGT_SCALE` version `nws-tulsa-text-reference-2026-09-11-v1` is immutable, source-attributed and contains literal labels/endpoints, no safety colors or activity mapping. `tulsaWbgtPosition({metric,valueC}, [minC,maxC])` returns marker fraction, unaltered value, clipping direction, source band index, or an explicit boundary value with null band. Celsius inputs compare against `(F−32)*5/9`; classification precedes display rounding. Missing/nonfinite values, invalid viewports and ordinary-wet-bulb/heat-index inputs produce no marker. A viewport is solely a graph extent, not additional heat thresholds.

Lead must export this standalone module from the heat package entry point if desired; that file was outside ownership. UI should show an actual unrounded-value marker, visible numeric value and valid timestamp, plus a link titled “NWS Tulsa WBGT reference bands.” At exact endpoints show “At a published boundary; endpoint rule unspecified.” For rounded values very close to a boundary, avoid text claiming exact boundary equality. At clipping, keep the actual value and an off-scale arrow. Keep category notifications disabled and existing activity education independent. A neutral numeric line/chart is usable without any personal risk classification.

## Concrete numerical input proposal

Proposed derivation ID: `liljegren-1.1-zindy-ts-1+fao56-eq47-10m+om-instant-v1`. The underlying calculation/version and full Argonne notices remain unchanged. Approve this explicitly as a **modeled outdoor short-grass reference exposure**, not measured local WBGT or universal local 2 m wind. This is a feasible implementation choice with transparent assumptions, not evidence that every location is grassy.

- Obtain `temperature_2m`, `relative_humidity_2m`, `surface_pressure`, `wind_speed_10m`, `shortwave_radiation_instant` together at identical hourly UTC instants, with Celsius/%/hPa/m/s/W/m² unit validation. Retain `shortwave_radiation` preceding-hour mean separately for provenance where available. Existing provider/schema already carry surface pressure; instantaneous GHI and calculation provenance still need lead integration.
- [FAO-56 chapter 3 equation 47 and example 14](https://www.fao.org/4/X0490E/x0490e07.htm#wind%20speed) give `u2 = uz * 4.87 / ln(67.8*z - 5.42)` above short grass. For z=10, factor is `0.7479510751679441`, not an unexplained 0.75 constant. Preserve raw 10 m wind and converted 2 m wind before the existing 0.13 m/s solver floor. No gust, terrain-by-city, nighttime gradient or actual shelter inference. The reference's stability-dependent height conversion is bypassed deliberately; this assumption is not approved by a numerical parity test alone.
- [Open-Meteo documentation](https://open-meteo.com/en/docs) lists instantaneous radiation alongside ordinary hourly mean radiation. Preserved [pinned source audit and four AK/HI samples](../research/heat-science.md#pinned-public-routing-what-instant-means) show endpoint GHI derived from backward means using solar geometry; public source pin `7988e4de62a3bf4e2ef4f3034a793af6e3bb3e84` is not a confirmed production revision. Pass this as `radiationAssumption='instantaneous'` and retain a separate description that it is provider-derived, not measured instant radiation. Do not copy AGPL server routines, supply DNI as GHI, assume clear sky, or silently replace missing instant GHI with hourly mean.
- Use returned series coordinates for solar geometry; preserve requested coordinates separately. One best-match response may combine models/grids, so do not claim exact per-field grid provenance. Use reference UTC time with seconds zero and avg=0. Do not mix actual-now temperature with last-hour radiation or label tomorrow's daytime maximum “current.” For a current card select the latest hourly instant at or before now, less than one hour old, from a fresh response; label “Hourly estimate at [time].” This one-hour selection rule is an engineering presentation bound, not a scientific validity interval. Missing eligible timestamp yields unavailable. Stale stored data may appear only with explicit stale/as-of text, never as a new current reading.
- On missing/nonfinite required values, wrong units, unsupported year/domain or any solver component failure, emit an explicit unavailable reason and no scale marker. Do not populate zero. Keep legitimate zero nighttime radiation and calm wind. Retain solver floor/cap, extrapolation warnings, natural-wet-bulb/globe component diagnostics, requested location, valid/retrieval times, provider/method and input policy version.

Recommended primary wording: “Estimated outdoor WBGT · short-grass reference.” Expanded explanation: wind is adjusted from modeled 10 m values, solar radiation is a modeled endpoint estimate, and shelter/surfaces/clothing/exertion can change individual exposure. Activity does not change this environmental number. Ordinary wet-bulb remains separately labeled and never enters this scale.
